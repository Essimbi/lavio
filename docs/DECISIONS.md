Mais elle impose : (1) d'envelopper **chaque requête** Prisma dans une transaction précédée de `set_config` (un aller-retour de plus par requête, sensible si la base est loin des utilisateurs), (2) de propager le contexte à la main dans chaque transaction interactive (numérotation, paiements), (3) un rôle PostgreSQL applicatif distinct du propriétaire (le propriétaire contourne la RLS) avec des droits à maintenir à chaque migration, ce que l'intégration Neon de Vercel ne fournit pas par défaut. **L'isolation reste applicative** (extension Prisma + `AsyncLocalStorage`, `tenant_id` issu du jeton, vérification de l'appartenance des clés étrangères) **et les tests d'isolation sont obligatoires pour chaque module**.
